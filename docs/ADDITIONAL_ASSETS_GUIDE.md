# Additional_assets.zip 상세 제작 안내

공개 플래셔는 저작권이 있는 추가 이미지와 음원을 포함하지 않습니다. 사용자가
직접 준비한 `Additional_assets.zip`을 PC 안에서 기기용 형식으로 변환합니다.
이 문서는 ZIP의 구조, 파일별 역할, 크기와 배치 규칙을 설명합니다.

추가 자산은 빈 폴더에서 새로 구성하지 말고 먼저
[배포용 샘플 ZIP](../samples/sample_Additional_assets.zip)을 내려받아 작업하세요.
그래픽은 샘플 이미지의 캔버스·실루엣·위치에 맞춰 새 그림으로 교체하고,
오디오는 샘플의 파일 이름을 기준으로 실제 MP3 또는 WAV를 준비하는 방식이
가장 안전합니다. 샘플을 수정하지 않고 그대로 설치해도 됩니다. 컴퓨터 사용과
압축 파일에 익숙하지 않다면 [처음 설치하기](INSTALLATION_GUIDE.md)부터 읽어
주세요.

## 1. 준비 전 권리 확인

다음 중 하나에 해당하는 파일만 사용하세요.

- 본인이 직접 그리거나 녹음·작곡한 파일
- 소프트웨어에 포함하고, 필요한 길이·크기·형식으로 수정할 권리를 명시적으로
  받은 파일
- 이용 조건상 비상업 소프트웨어 삽입과 변형이 허용되고, 요구되는 표시를
  모두 이행할 수 있는 파일

단순히 인터넷에서 내려받을 수 있다는 사실, 무료라는 표시, 개인 감상용 사용
허가는 소프트웨어 삽입·변환 권한과 같지 않습니다. 권리 범위가 불명확하면
사용하지 마세요. 공개 플래셔는 파일의 권리 상태를 판정하지 않습니다.

`Additional_assets.zip`과 이 ZIP을 넣어 만든 완성 펌웨어는 개인 설치용으로만
보관하고 제3자에게 재배포하지 마세요.

## 2. 정확한 ZIP 구조

아래 21개 항목이 모두 필요합니다. 오디오 하나에는 MP3와 WAV 중 **한 파일만**
넣어야 합니다. 음원을 사용하지 않을 항목은 샘플처럼 같은 이름의 **0바이트
파일**을 남겨 두면 해당 음원 없이 펌웨어를 만듭니다.

```text
Additional_assets.zip
├─ Visual
│  ├─ L01.png
│  ├─ B01.png
│  ├─ B02.png
│  ├─ S01.png
│  ├─ S02.png
│  ├─ S03.png
│  ├─ S04.png
│  ├─ D01.png
│  ├─ D02.png
│  ├─ D03.png
│  ├─ D04.png
│  └─ DD.png
└─ Audio
   ├─ P.mp3 또는 P.wav
   ├─ Care.mp3 또는 Care.wav
   ├─ C.mp3 또는 C.wav
   ├─ L.mp3 또는 L.wav
   ├─ E.mp3 또는 E.wav
   ├─ B.mp3 또는 B.wav
   ├─ BAT.mp3 또는 BAT.wav
   ├─ MIN.mp3 또는 MIN.wav
   └─ MAR.mp3 또는 MAR.wav
```

ZIP 안에 `내폴더/Visual`, `내폴더/Audio`처럼 상위 폴더가 하나 더 있어도
인식합니다. 파일명과 폴더명은 대소문자를 구분하지 않지만, 혼동을 피하려면
표기 그대로 사용하세요. 같은 항목의 MP3와 WAV를 모두 넣으면 중복 오류가
납니다.

Windows에서 만드는 가장 간단한 방법:

1. `sample_Additional_assets.zip`을 내려받아 압축을 풉니다.
2. `Visual` 폴더의 샘플 PNG를 열고, 기존 캔버스와 실루엣을 기준으로 새 그림을
   그린 뒤 **같은 파일 이름**으로 덮어씁니다.
3. `Audio` 폴더의 0바이트 표시 파일 이름을 확인합니다.
4. 사용할 오디오를 해당 이름의 MP3 또는 WAV **한 개**로 교체합니다. 음원을
   사용하지 않을 항목은 0바이트 표시 파일을 그대로 둡니다.
5. `Visual`과 `Audio` 두 폴더를 함께 선택합니다.
6. 마우스 오른쪽 버튼의 압축 기능으로 ZIP을 만듭니다.
7. 이름을 정확히 `Additional_assets.zip`으로 바꿉니다.
8. `TamaPoke-Flasher.exe`와 같은 폴더에 둡니다.

## 3. 이미지 공통 규칙

- 샘플 PNG를 작업용 틀로 사용하고 캔버스 크기와 그림 중심을 유지합니다.
- 샘플에 표시된 실루엣은 게임에서 실제로 보이는 대략적인 영역과 겹침 순서를
  안내합니다. 새 그래픽의 중요한 부분이 이 영역 안에 들어오도록 만드세요.
- 특히 `S01~S03`은 샘플 레이어를 겹쳐 보면서 각 부품의 위치를 맞추고,
  `D01~D04`와 `DD`는 샘플의 픽셀 크기와 땅굴 중심을 그대로 유지합니다.
- 형식: PNG
- 색상: 일반 RGB/RGBA PNG 권장
- 투명 배경이 필요한 파일은 알파 투명도를 사용합니다.
- 파일 가장자리에 불필요한 여백, 그림자, 반투명 테두리가 많으면 축소 후
  지저분해질 수 있습니다.
- 디그다 파일을 제외한 이미지는 권장 크기와 달라도 자동으로 출력 크기에
  맞춰집니다. 단, 원본 비율과 배치가 잘못되어 있으면 자동으로 고쳐지지
  않습니다.
- 플래셔는 최종 화면용 RGB565/RLE 형식으로 변환하므로 미세한 색 변화는
  줄어들 수 있습니다.

전체 배치 개념은 [이미지 배치 도식](ASSET_LAYOUT.svg)에서도 확인할 수 있습니다.

## 4. 이미지별 규격

| 파일 | 용도 | 준비 권장 크기 | 기기용 출력 | 배경 처리 |
|---|---|---:|---:|---|
| `L01.png` | 슬립 복귀 로딩 화면 | 350×350 | 350×350 | 검은 배경에 합성 |
| `B01.png` | 닫힌 포획 볼 | 160×160 | 160×160 | 검은 배경에 합성 |
| `B02.png` | 열린 포획 볼·포획 실패 | 160×160 | 160×160 | 검은 배경에 합성 |
| `S01.png` | 잠만보 머리·팔, 맨 뒤 레이어 | 350×350 | 116×116 | 투명 |
| `S02.png` | 잠만보 몸통, 가운데 레이어 | 350×350 | 116×116 | 투명 |
| `S03.png` | 잠만보 발, 맨 앞 레이어 | 350×350 | 116×116 | 투명 |
| `S04.png` | 잠에서 깬 잠만보 전체 모습 | 350×350 | 116×116 | 투명 |
| `D01.png` | 디그다 등장 1프레임 | **22×17 필수** | 22×17 | 투명 |
| `D02.png` | 디그다 등장 2프레임 | **22×17 필수** | 22×17 | 투명 |
| `D03.png` | 디그다 등장 3프레임 | **22×17 필수** | 22×17 | 투명 |
| `D04.png` | 디그다 등장 4프레임 | **22×17 필수** | 22×17 | 투명 |
| `DD.png` | 빈 땅굴 | **22×16 필수** | 22×16 | 투명 |

### L01 로딩 화면

350×350 전체가 원형 기기 중앙에 표시됩니다. 흰 글자나 밝은 그림을 검은
바탕에 사용할 목적으로 설계되어 있습니다. PNG의 투명 영역도 최종적으로는
검은색과 합성됩니다. 중요한 글자와 그림은 가장자리에서 최소 20px 이상
안쪽에 두세요.

### B01/B02 포획 볼

두 파일은 같은 160×160 캔버스와 같은 중심점을 사용해야 장면 전환 때 볼이
튀지 않습니다. `B01`은 닫힌 상태, `B02`는 열린 상태입니다. 포획 화면은 검은
배경이므로 반투명 회색 테두리보다 선명한 불투명 외곽선이 안정적입니다.

### S01~S04 잠만보 레이어

네 파일은 **완전히 같은 350×350 캔버스, 같은 원점, 같은 배율**로 만들어야
합니다. 각 파일에서 필요 없는 부분을 지우되 남은 부품을 이동시키면 안 됩니다.

게임의 합성 순서:

```text
맨 앞  S03 발
가운데 S02 몸통        ← 일반 타격 때 이 레이어만 좌우로 흔들림
맨 뒤  S01 머리·팔

100점 도달 후에는 세 레이어 대신 S04 전체 그림으로 교체
```

즉, 원본 한 장을 복제해 네 파일을 만든 다음 같은 위치를 유지한 채 레이어별로
불필요한 부분만 투명하게 지우는 방식이 안전합니다. `S01`+`S02`+`S03`을 같은
좌표에 겹쳤을 때 완전한 잠만보 한 장이 보여야 합니다. 플래셔는 네 이미지를
같은 63색 팔레트로 줄이고 각각 116×116으로 축소합니다. 게임에서는 이를
3배로 확대해 약 348×348 영역에 표시합니다.

흰 배경을 투명하게 만들기 위해 플래셔가 주변 색을 정리하지만, 대상과 배경의
색이 비슷하면 일부가 지워질 수 있습니다. 가능하면 처음부터 투명 PNG로
준비하고, 얇은 반투명 그림자나 회색 격자 배경은 제거하세요.

### D01~D04/DD 디그다

이 다섯 파일은 크기가 다르면 플래셔가 설치를 중단합니다. 자동 축소되지
않습니다.

- `D01` → `D02` → `D03` → `D04` 순서로 땅굴에서 올라오는 동작이 자연스럽게
  이어져야 합니다.
- 다섯 파일의 땅굴 중심과 캐릭터 중심을 같은 x좌표에 맞춥니다.
- 프레임마다 땅굴 위치가 움직이면 게임에서 떨려 보입니다.
- `DD`는 캐릭터가 없는 빈 땅굴입니다.

## 5. 오디오 공통 규칙

- 샘플 `Audio` 폴더의 파일 이름이 각 장면과 연결되는 식별자입니다. 원하는
  음원을 준비하더라도 `P`, `Care`, `C`, `L`, `E`, `B`, `BAT`, `MIN`, `MAR`
  중 해당 이름을 그대로 사용해야 합니다.
- 샘플의 0바이트 파일을 실제 음원으로 교체할 때는 MP3 또는 WAV 중 하나만
  남깁니다. 예를 들어 `BAT.wav`를 `BAT.mp3`로 교체했다면 기존 0바이트
  `BAT.wav`는 삭제해야 합니다.
- 0바이트 MP3/WAV: 해당 음원을 생략한다는 표시 파일
- 입력 형식: MP3 또는 WAV
- 출력 형식: 16kHz, 모노, IMA-ADPCM
- 스테레오는 모노로 합쳐집니다.
- 긴 파일은 아래 시간 규칙에 맞춰 잘립니다.
- 음량은 항목별 목표 피크로 자동 정규화됩니다.
- 지정된 마지막 구간은 선형 페이드아웃됩니다.
- 원본 앞뒤의 긴 무음은 직접 정리해 두는 편이 결과를 예측하기 쉽습니다.

| 이름 | 장면 | 필요한 입력 길이 | 실제 사용 구간 | 끝 페이드 |
|---|---|---:|---:|---:|
| `P` | 특별 파트너 등장음 | 0.1초 이상, 최대 4초 사용 | 무음 제거 후 최대 4초 | 매우 짧게 |
| `Care` | 케어 알림음 | 0.1초 이상, 최대 10초 사용 | 무음 제거 후 최대 10초 | 매우 짧게 |
| `C` | 포획 성공음 | 0.1초 이상, 최대 10초 사용 | 처음부터 최대 10초 | 0.1초 |
| `L` | 저체력 알림음 | 0.1초 이상, 최대 6초 사용 | 처음부터 최대 6초 | 0.05초 |
| `E` | 진화 장면 | **6.2초 이상** | 1.0초부터 5.2초 | 2초 |
| `B` | 작별 장면 | **10초 이상** | 처음 10초 | 2초 |
| `BAT` | 야생·통신 배틀 BGM | **60초 이상** | 처음 60초 | 5초 |
| `MIN` | 산책을 제외한 미니게임 BGM | **60초 이상** | 처음 60초 | 5초 |
| `MAR` | 통신 짝짓기 연출 BGM | **15.5초 이상** | 처음 15.5초 | 5초 |

음원을 사용하지 않으려면 표의 길이를 맞춘 무음 파일을 만들 필요가 없습니다.
샘플 ZIP에 들어 있는 0바이트 파일을 그대로 두세요. 플래셔는 0바이트 파일을
오류로 해석하지 않고 해당 기기용 음원 파일을 생성하지 않습니다. 이 경우
장면에 따라 펌웨어의 기본 합성 효과음이 재생되거나 BGM 없이 진행됩니다.

`BAT`는 배틀이 60초를 넘으면 다시 처음부터 반복됩니다. `MIN`은 1분 제한
미니게임에 맞춘 길이이며 산책에는 재생되지 않습니다. 음원은 장면에 맞게
자동으로 잘릴 뿐, 연출 시간이 음원에 맞춰 늘어나지는 않습니다.

## 6. 플래셔 검증과 변환

플래셔는 설치 전에 다음을 검사합니다.

- 21개 필수 항목의 누락과 중복
- MP3/WAV 동시 입력
- 0바이트 오디오는 정상적인 음원 생략 표시로 처리
- ZIP 내부의 상위 경로 이동(`..`), 절대 경로와 심볼릭 링크
- 128개를 넘는 파일, 256MB를 넘는 전체 압축 해제 크기
- 80MB를 넘는 단일 파일
- 디그다 이미지의 정확한 픽셀 크기
- 고정 길이 BGM·진화 음원의 최소 재생시간

ZIP 내용 전체의 SHA-256을 자산 캐시 키에 포함합니다. 파일 하나를 바꾸면 새
변환 결과와 새 펌웨어가 만들어지고, 동일한 ZIP은 기존 캐시를 재사용합니다.

## 7. 자주 발생하는 문제

### “누락” 오류

ZIP을 열어 `Visual`과 `Audio` 폴더가 실제로 들어 있는지 확인하세요. 파일
확장자가 숨겨진 Windows에서 `L01.png.png`처럼 중복 확장자가 생기지 않았는지
확인합니다.

### “중복” 오류

한 오디오 이름에 MP3와 WAV를 함께 넣지 마세요. ZIP 안의 백업 폴더에 같은
이름의 파일이 하나 더 있어도 중복으로 감지됩니다.

실제 MP3를 넣으면서 샘플의 0바이트 WAV를 남겨 둔 경우에도 중복입니다. 실제
음원을 넣은 뒤 같은 이름의 빈 표시 파일은 삭제하세요.

### 잠만보가 조각나 보임

S01~S03의 캔버스 크기, 캐릭터 위치와 중심점이 서로 다릅니다. 같은 원본
캔버스를 복제해 다시 분리하세요.

### 이미지에 흰 사각형이 보임

투명해야 하는 이미지가 흰 배경으로 저장된 상태입니다. PNG 알파 투명도를
확인하세요. L01/B01/B02는 검은 배경 합성이 정상입니다.

### 새 ZIP이 적용되지 않음
